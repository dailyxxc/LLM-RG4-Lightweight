# BN5212-final-VLMR 与 LLM-RG4-original 项目关系与功能对比

## 📋 项目关系

### 基础关系

**BN5212-final-VLMR** 是基于 **LLM-RG4-original** 的**扩展和改进版本**。

- **LLM-RG4-original**: 原始项目，实现了LLM-RG4论文（AAAI 2025 Oral）的基础功能
- **BN5212-final-VLMR**: 师兄的毕业设计项目，在LLM-RG4基础上添加了**检索增强生成（RAG）**和**自增强迭代生成（SAIA）**功能

### 项目信息

| 项目 | 来源 | 主要功能 | 论文/项目 |
|------|------|----------|-----------|
| **LLM-RG4-original** | 官方实现 | 基础的多场景报告生成 | LLM-RG4 (AAAI 2025) |
| **BN5212-final-VLMR** | 师兄扩展 | RAG + SAIA增强的报告生成 | NUS-BN5212项目 |

## 🎯 核心功能对比

### LLM-RG4-original 核心功能

1. **四种场景支持（RG4）**
   - sn: Single-view, No prior report
   - sw: Single-view, With prior report
   - mn: Multi-view, No prior report
   - mw: Multi-view, With prior report

2. **两阶段训练**
   - Stage 1: 训练视觉-文本对齐（APPA模块）
   - Stage 2: LoRA微调LLM + 多模态融合

3. **模型架构**
   - 视觉编码器（rad-dino）
   - 文本编码器（CXR-BERT）
   - APPA模块（对齐和投影）
   - Lateral分支（侧位图像）
   - Text分支（历史报告）
   - IIT融合（Image-Image-Text）
   - LLM（Vicuna/Tiny-Vicuna）

4. **损失函数**
   - Token级别交叉熵损失
   - 句子加权损失（λ=0.75）

### BN5212-final-VLMR 新增功能

#### 1. **RAG (Retrieval-Augmented Generation) - 检索增强生成**


#### 2. **SAIA (Self-Augmented Iterative Augmentation) - 自增强迭代生成**

**功能描述**：
- **两阶段生成**：
  1. **第一阶段**：生成初始草稿报告
  2. **第二阶段**：将第一阶段生成的草稿作为RAG输入，生成最终报告

**工作流程**：
```
输入图像 → 第一阶段生成 → 草稿报告
                ↓
        草稿报告作为RAG输入
                ↓
输入图像 + RAG(草稿) → 第二阶段生成 → 最终报告
```

**优势**：
- 利用模型自身生成的草稿作为上下文
- 提高报告的连贯性和准确性
- 减少幻觉（hallucination）

#### 3. **增强的损失函数**

**原始损失**（LLM-RG4）：
```
Loss = Token_CE_Loss + λ * Sentence_Weighted_Loss
     = average_loss + 0.75 * key_loss
```

**增强损失**（BN5212-final-VLMR）：
```
Loss = Token_CE_Loss + λ * Sentence_Weighted_Loss + γ * RAG_Auxiliary_Loss
     = average_loss + 0.75 * key_loss + 0.1 * rag_loss
```

**RAG辅助损失的作用**：
- 鼓励模型使用检索到的RAG内容
- 通过注意力机制监控RAG利用率
- 提高生成质量

## 🎓 师兄项目的创新点

### 1. RAG增强生成

**问题**：
- 模型可能生成与输入无关的内容（幻觉）
- 缺乏外部知识支持

**解决方案**：
- 检索相似的历史报告
- 将检索内容编码并融合到生成过程
- 通过交叉注意力机制对齐

**实现细节**：
```python
# RAG编码流程
rag_text → BERT编码 → 交叉注意力（query_feature）→ 投影 → LLM embedding

# 提示词格式
"Human: <Img><ImageHere></Img> Using the following relevant information: 
<RAG><RAGHere></RAG> {prompt_text}. \nAssistant:"
```

### 2. SAIA两阶段生成

**问题**：
- 单次生成可能不够准确
- 缺乏自我修正机制

**解决方案**：
- 第一阶段：生成草稿报告
- 第二阶段：将草稿作为RAG输入，生成最终报告

**优势**：
- 利用模型自身生成的内容作为上下文
- 提高报告的连贯性
- 减少错误和幻觉

### 3. RAG辅助损失

**设计思想**：
- 监控RAG内容的利用率
- 鼓励模型使用检索到的信息
- 通过注意力机制优化

**实现**：
```python
# 计算RAG注意力
rag_attention = torch.bmm(output_embeds, rag_embeds.transpose(1, 2))

# RAG辅助损失（鼓励使用RAG内容）
rag_loss = -0.1 * torch.clamp(rag_attention, min=0.01, max=1.0)
total_loss = total_loss + rag_loss
```

## 📈 预期效果

### RAG的预期效果

1. **减少幻觉**：
   - 通过检索相关报告，提供真实参考
   - 减少生成与输入无关的内容

2. **提高准确性**：
   - 利用外部知识库
   - 生成更符合医学规范的报告

3. **增强一致性**：
   - 参考相似案例
   - 保持报告风格一致

### SAIA的预期效果

1. **提高质量**：
   - 两阶段生成，自我修正
   - 最终报告更准确、更完整

2. **减少错误**：
   - 第一阶段可能遗漏的信息
   - 第二阶段通过RAG补充

3. **增强连贯性**：
   - 草稿作为上下文
   - 最终报告更连贯

## 📝 总结

### 项目定位

- **LLM-RG4-original**: 基础框架，实现了灵活的多场景报告生成
- **BN5212-final-VLMR**: 在基础框架上添加RAG和SAIA，提高生成质量和准确性

### 核心创新

1. **RAG增强**：利用外部知识库，减少幻觉，提高准确性
2. **SAIA机制**：两阶段生成，自我修正，提高质量
3. **损失优化**：RAG辅助损失，鼓励使用检索内容
